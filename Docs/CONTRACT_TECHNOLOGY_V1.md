# CONTRACT TECHNOLOGY V1 — 하청으로 기술을 쌓아 자체 제품으로 간다

매드게임즈타이쿤·카이로 게임개발 계열의 성장 고리를 이 게임의 정본으로 만든 문서다.
**하청을 받아 돈을 벌고, 그 일을 하면서 얻은 기술로 자체 제품을 연다.**

## 계약 완료 보상은 돈과 기술 두 개다

한 줄로 합치지 않는다. 계약 카드와 완료 알림 모두 두 줄로 분리해 표시한다.

```text
[하청] 종로 타자학원 — 타자 연습 프로그램 단어 DB 입력
보상  ₩720,000
기술  DB 설계 +40pt · 자료 입력 +15pt
마감  7일 / 작업 26인시 · 2명 권장
```

- 돈은 `SubcontractOffer.RewardWon`이 소유하고 회사 현금으로 정산된다.
- 기술은 `ContractTechnologyGrantCatalog`가 소유하고 `CompanyGrowthState.Technology`에 누적된다.
- 둘은 서로를 참조하지 않는다. **보수는 좋지만 배울 것이 없는 일**과 **싸지만 제품 경로를 여는 일**이
  모두 성립해야 하기 때문이다. `PrototypeValidation`이 기술 라벨에 `₩`가 들어가면 실패시킨다.

## 레벨 규칙

| 누적 포인트 | 레벨 | 표기 |
| --- | --- | --- |
| 0 | 0 | `미습득` |
| 1~99 | 1 | `Lv1 40/100` |
| 100~199 | 2 | `Lv2 30/100` |
| … | … | |
| 400 이상 | 5 | `Lv5 숙련` |

- 첫 1포인트가 Lv1이다. 한 번이라도 해 본 일과 아예 안 해 본 일을 구분하기 위해서다.
- 이후 `CompanyTechnologyCatalog.PointsPerLevel`(100)마다 한 레벨, 최대 `MaximumLevel`(5).
- 포인트는 절대 줄지 않는다. 기술은 쓴다고 닳지 않는다.

## 기술 목록 — 25종

정본은 `Simulation/Technology/CompanyTechnologyCatalog.cs`다. 모든 기술은 **하청으로 반드시 얻을 수
있어야 한다**. 검증기가 카탈로그의 모든 기술이 최소 한 계약에서 나오는지 확인하고, 아니면 실패시킨다.

| 트랙 | 기술 |
| --- | --- |
| 웹·소프트 | 도트 그래픽 · 웹 퍼블리싱 · 자료 입력·타이핑 · DB 설계 · 플래시 애니메이션 · 서버 운영 · 관리자 툴 · 재고 전산 |
| 모바일 | 벨소리·사운드 · 피처폰 UI · 다기종 포팅 · 모바일 게임 로직 |
| 하드웨어 | PC 조립·번인 · 기판·키패드 조립 · 미디어 복제·포장 · 사무 네트워크 · 유즈맵·스크립팅 |
| 리테일·오프라인 | 납품·물류 · 자수·인쇄 · 전단·스티커 디자인 · 상품 촬영 |
| 공통 | 품질 검수 · 3D 모델링 · 자동화 라인 · 소비자 시장 분석 |

`3D 모델링`·`자동화 라인`·`소비자 시장 분석`은 기존 `ResearchTechnologyIds`의 문자열을 그대로 쓴다.
저장 파일과 기존 제품 요구 조건이 계속 유효해야 하기 때문이다. 이 셋은 **돈으로 사는 연구**와
**하청으로 쌓는 레벨**을 둘 다 가진다. 돈은 면허를 사고, 일은 숙련을 산다.

## 계약별 기술 — 21개 전부 손으로 지정

계열에서 자동 유도하지 않는다. "이 일이 정확히 무엇을 가르치는가"가 요청의 핵심이라 21개 부트스트랩
템플릿마다 직접 적었다. 정본은 `Simulation/Technology/ContractTechnologyGrantCatalog.cs`이며 인덱스는
`BootstrapContractCatalog`의 안정적인 템플릿 순서다.

예시:

| 계약 | 기술 |
| --- | --- |
| 미니홈피용 64×64 아바타 도트 | 도트 그래픽 +40 · 웹 퍼블리싱 +10 |
| 타자 연습 프로그램 단어 DB 입력 | DB 설계 +40 · 자료 입력 +15 |
| 초창기 P2P 서버 야간 모니터링 | 서버 운영 +70 · 사무 네트워크 +20 · 자동화 라인 +25 |
| 모바일 맞고·타이쿤 다기종 포팅 | 다기종 포팅 +70 · 모바일 게임 로직 +30 · 자동화 라인 +15 |
| 동대문 도매 의류 재고 전산화 | 재고 전산 +55 · DB 설계 +25 |

큰 일일수록 많이 가르친다. 주 기술 하나에 부 기술 1~2개를 붙여, 한 계열만 파도 부 기술이 천천히 같이
오르게 했다.

## 자체 제품 요구 기술

제품은 **그 산업의 하청이 실제로 가르치는 기술**만 요구한다. 그래야 "이 일을 계속 받으면 저 제품이
열린다"가 플레이 중에 보인다.

| 자체 제품 | 요구 기술 |
| --- | --- |
| 웹 서비스·PC 소프트웨어 | DB 설계 Lv2 · 웹 퍼블리싱 Lv1 · 서버 운영 Lv1 |
| 피처폰 콘텐츠·모바일 게임 | 피처폰 UI Lv2 · 다기종 포팅 Lv1 · 벨소리·사운드 Lv1 |
| PC 주변기기·디지털 기기 | 기판·키패드 조립 Lv2 · PC 조립·번인 Lv1 · 품질 검수 Lv1 |
| 상점 전산화·유통 브랜드 | 재고 전산 Lv2 · 관리자 툴 Lv1 · 상품 촬영 Lv1 |

기존의 현금·평판·하청 건수·시장 보고서 조건은 그대로 남는다. 기술 조건은 그 위에 추가된 축이며,
진행률은 요구 건마다 평균 내어 "한 레벨 모자람"이 0%로 보이지 않게 한다. 제품 카드에는
`쌓은 기술 DB 설계 Lv1/2 · 웹 퍼블리싱 Lv1/1`처럼 무엇이 모자란지 그대로 적는다.

## 저장

- 스키마 `v11`. `growth.technologyPoints`에 `technologyId`/`points` 쌍으로 저장한다.
- `v10` 이하는 기술 원장이 없으므로 누적 0으로 시작한다. 삭제나 추정 없이 그대로 이관된다.
- 0포인트 기술은 저장하지 않는다. 스냅샷은 카탈로그 순서로 안정 정렬된다.

## 검증

`FamilyCompany.Editor.PrototypeValidation.ValidateContractTechnologyRewards`가 확인한다.

```text
CONTRACT_TECHNOLOGY_REWARD_VALIDATION: PASS | technologies=25 contracts=21 schema=11
```

- 카탈로그의 모든 기술이 최소 한 계약에서 나온다
- 21개 계약 전부가 기술 지급을 선언한다
- 레벨 경계 0/1/99/100/상한
- 같은 계약을 반복하면 레벨이 오른다
- 기술 포인트가 저장 왕복에서 보존된다
- 기술 라벨에 현금 기호가 섞이지 않는다

## 상위 하청은 기술을 요구한다

기술이 나오기만 하고 아무 문도 열지 않으면 성장 고리가 아니다. 21개 중 **10개는 누구에게나 열려
있고**(기술 0인 회사도 언제나 첫 포인트를 벌 수 있어야 한다), **11개가 게이트를 가진다**. 정본은
`Simulation/Technology/ContractTechnologyRequirementCatalog.cs`다.

| 계약 | 요구 기술 |
| --- | --- |
| 엽기 플래시 애니메이션 프레임 채색 | 도트 그래픽 Lv2 |
| 초창기 P2P 서버 야간 모니터링 | 사무 네트워크 Lv1 |
| 모바일 맞고·타이쿤 다기종 포팅 | 피처폰 UI Lv2 |
| MP3 플레이어 메인보드 조립·용량 검수 | 기판·키패드 조립 Lv2 · 품질 검수 Lv1 |
| 동대문 도매 의류 재고 전산화 | DB 설계 Lv2 |

- 요구는 언제나 **보유/필요**로 적는다: `필요 기술 DB 설계 Lv1/2`.
- 잠긴 계약은 카드 글자가 흐려지고 배정 라벨이 `회사 기술 부족`이 된다.
- 수락 차단은 `ContractPortfolio.TryAccept`에 있다. UI를 우회해도 통과할 수 없다.

**막다른 길이 없다는 것을 시뮬레이션으로 증명한다.** 검증기가 기술 0에서 시작해 그 시점에 받을 수 있는
계약만 반복 수행하고, 21개 전부가 열리는지 그리고 자체 제품 4종의 요구 기술이 전부 하청만으로 도달
가능한지 확인한다. 하나라도 못 열면 실패한다.

## 숙련은 작업을 빠르고 좋게 만든다

정본은 `Simulation/Technology/CompanyTechnologyBonusRules.cs`다.

- 한 계약의 **숙련도**는 그 일이 가르치는 기술들에 대한 회사 레벨을 **지급 포인트로 가중 평균**한 값이다.
  DB 작업이 대부분인 계약은 부수 기술이 아니라 DB 레벨이 끌고 간다.
- Lv1까지는 중립이다. 한 번 해 본 것으로는 아직 빨라지지 않는다.
- 그 위로 한 레벨마다 **작업 속도 +5%**, **품질 +3점**. 완전 숙련은 **+20%**다.
- 절대 중립 아래로 내려가지 않는다. 경험이 사람을 느리게 만들지는 않는다.
- 숙련도는 advance 전체에서 **상수로 고정**한다. 이번 계약을 끝내서 오른 레벨은 다음 계약부터
  적용된다. 계약 도중 속도가 변하면 결정론이 깨진다.

계약 카드에 `기술 숙련 Lv3 · 작업 속도 +10%`로 표시하고, 결과의 `WorkRateBasisPoints`로 "왜 이번엔
빨랐는지"를 설명할 수 있다.

## 연구 허브 · 보유 기술 화면

`연구 → 보유 기술`이 25종의 레벨을 트랙별로 보여준다. 하청 카드와 완료 알림 말고 기술을 확인할 수 있는
유일한 화면이라, 배지 하나가 아니라 레벨·레벨 내 진행도를 함께 적는다.

- 미습득 기술은 흐리게, 보유 기술은 진하게 표시한다.
- 아직 아무것도 없으면 "사업 허브의 하청을 완료하면 그 일이 가르치는 기술이 여기 쌓입니다"로 안내한다.

## 아직 안 한 것

- 품질 보너스는 계산되지만 아직 완료 품질 판정에 연결되지 않았다. 작업 속도만 실제로 적용된다.
- 기술로 해금되는 **가구·직원 역할**은 없다. 지금 기술은 계약 게이트, 작업 속도, 제품 해금 세 곳에만 쓴다.
- 기술별 아이콘이 없어 보유 기술 화면은 글자만으로 구성된다.
