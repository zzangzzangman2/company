# DO NOTS

이 문서는 가족회사 프로젝트에서 반복하지 말아야 할 실패 방향을 모은다. 짧고 절대적인 규칙은 루트 `AGENTS.md`가 최우선이며, 충돌하면 `AGENTS.md`를 따른다. `C:/Users/godho/Documents/Codex/simul`은 읽기 전용 참고 저장소이므로 어떤 경우에도 수정하지 않는다.

## 실제 회사와 미래 누설

- 실제 회사의 미래 제품, 부도, 상장폐지, 인수, 경영진 교체와 성공 여부를 그 정보가 공개된 게임 날짜보다 먼저 UI·뉴스·대사·도움말에 노출하지 않는다.
- `HistoricalBaseline` 전체나 숨은 사건 조건을 화면 계층에 직접 넘기지 않는다. 날짜 제한 resolver가 공개 가능한 사실만 반환하게 한다.
- 현재 날짜 이후의 회사명, 상장 상태, 재무 결과와 사건 `outcome`을 자동완성·검색 결과·디버그가 아닌 일반 화면에 섞지 않는다.
- 실제 역사 사건을 날짜가 왔다는 이유만으로 강제 재생하지 않는다. 회차의 선행 조건이 바뀌면 취소·지연·대체·이전 정책을 따른다.
- 실제 회사 사실과 회차에서 생성된 가격·계약·제품 성과를 같은 종류의 검증된 역사 기록처럼 표현하지 않는다.
- 로컬 뉴스에는 현재까지 공개된 세계 상태만 입력한다. 플레이어의 숨은 선택, 미래 후보 사건, 다음 가격 경로를 기사 재료로 사용하지 않는다.
- 실제 회사의 가치나 규모를 초기 플레이 편의를 위해 임의로 낮추지 않는다. 초기 인수는 근거 있는 자산·사업부·장비·계약·인력 단위로 제공한다.

## 의미 상태와 파생값

- 저장 파일에는 의미 상태만 기록한다. Transform, 웨이포인트 경로, 렌더 캐시, 열려 있는 탭, 선택 카드와 임시 UI 문구를 저장하지 않는다.
- 가족의 상태 라벨·관계 라벨·기분 문구, 계약 마감 압력, 예상 완료일, 가용 인시 합계처럼 원본 상태에서 다시 계산할 수 있는 파생값을 저장하지 않는다.
- 날짜별 실제 회사 표시명, 현재 상장 종목과 공개 뉴스 목록을 저장 사본으로 굳히지 않는다. 불변 ID와 현재 시각에서 다시 해석한다.
- 파생값 계산 비용이 크면 버전이 명시된 런타임 캐시를 사용하되 정본 상태와 혼동하거나 저장 스키마를 올리는 이유로 삼지 않는다.
- 돈은 정수 원 `long`, 시간은 캠페인 시작 이후 정수 분, 확률은 world seed와 안정 키로 다룬다. 표시용 소수·반올림 값을 원장에 되쓰지 않는다.
- 스키마를 올릴 때 기존 저장을 버리거나 새 필드의 기본값을 우연한 역직렬화 결과에 맡기지 않는다. 명시적인 이전 규칙과 왕복 검증을 둔다.

## 가족 시간표

- 가족을 하루 24시간 사용할 수 있는 직원 슬롯으로 취급하지 않는다. 학교·외부 영업·가사·개인 일정·수면 중에는 회사 인시를 만들지 않는다.
- 시간표 예외를 Presentation 계층이나 버튼 활성화 코드에 따로 복제하지 않는다. `FamilyScheduleRules`와 순수 시뮬레이션의 한 경로에서 판정한다.
- 플레이어가 시간을 크게 건너뛸 때 중간 30분 경계를 생략하지 않는다. 하루 점프와 같은 기간의 시간 분할은 같은 의미 상태를 만들어야 한다.
- 단순 메뉴 열기, 화면 이동, 취소된 행동에 시간을 차감하지 않는다. 의미 행동이 확정된 뒤에만 시간을 진행한다.
- 가족의 외부 일정을 플레이어가 매시간 다시 지정하게 만들지 않는다. 반복 시간표는 자동 적용하고 플레이어는 예외와 우선순위만 선택하게 한다.
- 14살 플레이어에게 성인 명의의 계약·은행·고용 권한을 직접 부여하지 않는다. 법적 행동은 성인 가족의 역할과 관계를 거친다.

## 계약과 회사 운영

- 계약을 클릭 한 번의 확정 수익으로 만들지 않는다. 인시·현금·납기·평판·관계 중 의미 있는 비용이 있어야 한다.
- 가족의 실제 가용 슬롯을 무시한 고정 인시 상한만으로 계약 가능 여부를 판단하지 않는다.
- NPC가 업무 목적지에 도착하고 체류를 마치기 전에 계약 인시를 반영하지 않는다. 이동 중 저장·불러오기에서도 중복 완료를 허용하지 않는다.
- 크런치와 커피를 원래 수락할 수 없는 계약을 무제한 수행하는 우회로로 만들지 않는다. 비상 효율에는 체력·스트레스·회복 시간의 후속 비용을 남긴다.
- 같은 `offerId`, 작업 intent, 원장 transaction을 두 번 수락·완료·정산하지 않는다.
- 납기 경계를 큰 시간 점프로 건너뛰었다고 완료와 실패 순서가 뒤집히지 않게 한다. 사건은 시각·우선순위·안정 ID 순으로 해결한다.
- 실제 고객은 불변 `companyId`로 참조하고 날짜별 표시명으로 보여 준다. 화면 문자열을 저장·계약 정체성으로 사용하지 않는다.
- 가족의 높은 신뢰를 무료 노동과 무한 야근 보너스로 바꾸지 않는다. 도움에는 피로와 다음 일정의 기회비용을 남긴다.

## 자율 행동 AI

- 장기 자율 상태를 MonoBehaviour·ScriptableObject가 소유하게 하지 않는다. 순수 C# 상태가 행동, 시작·종료 시각, 쿨다운과 누적 결과를 소유한다.
- `UnityEngine.Random`이나 호출 횟수에 따라 달라지는 RNG stream을 사용하지 않는다. seed, 날짜·분, actor/pair ID, 행동 종류와 sequence로 안정 키를 만든다.
- 컬렉션 순회 순서가 행동 결과를 바꾸게 두지 않는다. 후보와 자원 경쟁은 명시적인 점수·우선순위·ID 순으로 정렬한다.
- 이동 중이라는 이유로 상태 라벨을 매 프레임 업무와 이동 사이에서 깜빡이게 하지 않는다. 마지막 의미 행동과 읽기 쉬운 문자·색을 유지한다.
- 휴식, 커피, 수면과 화해를 반복해 체력·관계를 무한 파밍하게 하지 않는다. 쿨다운, 하루 상한, 반동과 원인 사건 연결을 둔다.
- 체력·스트레스가 0~100을 벗어나거나 한계 상태의 가족이 계속 일반 업무를 수행하게 하지 않는다. 강제 회복에는 종료 조건과 재진입 방지가 있어야 한다.
- 일상 수다를 모두 영구 관계 기억으로 저장하지 않는다. 중요한 갈등·화해·계약 위기만 남기고 오래된 상세 기억은 요약 가능하게 설계한다.
- 작은 자율 사건마다 모달을 띄우지 않는다. 월드 행동과 상태 라벨로 보여 주고 중요한 위기만 알림으로 승격한다.

## 2000~2026 장기 성능과 검증

- 27년 전체 연표, 모든 회사, 모든 가족 기억을 매 프레임 다시 계산·정렬·JSON 파싱하지 않는다.
- 화면 표시를 위해 30분 펄스 전체를 처음부터 재생하지 않는다. 상태는 증분 처리하고 조회용 집계는 필요할 때 캐시한다.
- 사건·관계 기억·완료 intent와 로그 목록을 무한히 키우지 않는다. 최근 상세, 고중요도 기억과 연도별 집계의 보존 상한을 둔다.
- 장기 시뮬레이션을 단일 seed 하나로 통과시키지 않는다. 복수 seed에서 결정론, 상태 범위, 성공·실패와 행동 분포를 함께 검사한다.
- 평균만 보고 특정 seed의 붕괴를 숨기지 않는다. 모든 seed에 적용되는 불변식과 전체 분포에 적용되는 다양성 조건을 분리한다.
- 하루 점프만 검증하거나 짧은 tick만 검증하지 않는다. 같은 기간의 큰 점프와 분할 진행 상태 해시를 비교한다.
- 저장 왕복 없이 장기 테스트를 통과로 기록하지 않는다. 현재 스키마와 지원하는 구형 스키마의 이전을 별도로 검증한다.
- 렌더·입력·씬 오브젝트가 없는 순수 로직 검증을 유지한다. 시각 검증과 경제·결정론 검증을 한 테스트의 우연한 환경에 묶지 않는다.

## 화면과 시대 표현

- 기존 `simul`의 세로 모바일 UI, 화면 구조, 좌표, 패널 비율을 그대로 복사하지 않는다. 이관 대상은 규칙·데이터·라이선스가 확인된 에셋·검증 교훈뿐이다.
- 가족회사 화면은 기존 `DECISIONS.md`대로 1920×1080 PC 가로 풀화면과 16:9를 기준으로 새로 배치하고, 넓은 사무실과 여러 가족의 실제 행동을 동시에 읽을 수 있게 한다.
- 새 화면 비주얼이 필요하면 밝고 캐주얼한 가로형 ImageGen 비주얼을 먼저 만들되 제목, 글자, 버튼과 동적 수치를 이미지에 굽지 않는다. 모든 조작 UI와 상태 문구는 Unity에서 별도 레이어로 그린다.
- 2000년 사무실에 스마트폰, 현대식 메신저·클라우드 UI, 평면 모니터와 시대 이후 제품을 넣지 않는다.
- 등급과 상태를 색 하나로만 표현하지 않는다. 색과 함께 짧은 문자 라벨을 제공한다.
- 실제로 이동하지 않는 가짜 직원을 배경 장식으로 추가하지 않는다. 회사 구성원은 의미 위치와 실제 월드 위치를 가진다.
- 주식·경영 화면을 별도 미니게임처럼 회사 생활과 단절시키지 않는다. 회사 현금, 시간, 가족 역할과 같은 정본 상태를 사용한다.
- 원화 크기의 이미지를 작은 월드 스프라이트와 매 프레임 UI에 그대로 사용하지 않는다. 런타임 규격과 캐시를 지킨다.

## 작업 방식과 문서

- 사용자나 다른 작업자가 수정 중인 파일을 확인하지 않고 덮어쓰거나 되돌리지 않는다.
- 같은 규칙과 현재 상태를 여러 문서에 복사해 각기 다르게 유지하지 않는다. 금지 규칙은 이 문서, 정본 설정은 `CANON.md`, 구조는 `ARCHITECTURE.md`, 방향 결정은 `DECISIONS.md`, 진행 상태는 `PROJECT_STATE.md`를 소유자로 삼고 다른 문서는 링크한다.
- 제안서를 정본처럼 취급하지 않는다. 채택된 방향만 소유 문서에 날짜와 이유를 남긴다.
- 완료하지 않은 기능이나 실행하지 않은 테스트를 완료로 기록하지 않는다. 실패·미실행은 이유와 다음 명령을 함께 남긴다.
- 코드·데이터·문서에서 같은 상수나 사건 정의를 중복 생성하지 않는다. 하나의 정본 정의와 resolver를 사용한다.
- `simul`에서 코드를 그대로 복사하거나 파생 수치 데이터를 이관하지 않는다. 구조와 검증 교훈을 참고해 가족회사 순수 C# 규칙으로 다시 작성한다.
- 빌드·저장 마이그레이션·장기 검증 실패를 숨기거나 통합하지 않는다.
