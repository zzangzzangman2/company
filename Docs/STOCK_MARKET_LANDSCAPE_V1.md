# 주식시장 가로 풀화면 V1

## 범위와 기준

- 원본 기준: `simul/flutter_app/lib/stock_market_screen.dart`, `stock_market_order_workspace.dart`, `game/order_book.dart`.
- Unity 화면은 원본 모바일 화면의 정보 순서와 거래 의미를 유지하되 4열 PC 화면으로 재배치한다.
- 화면 색은 SIMUL의 밝은 흰색/회색 바탕, 파란 매도, 빨간 매수를 사용한다. 글자·숫자·버튼은 Unity UI로 그린다.
- 기업 목록은 Korea History V1에서 해당 날짜에 실제 상장된 국내 기업만 가져온다.

## 보존 계약

- 1차 메뉴: 홈 → 종목 → 내 투자.
- 종목 상세: 호가 → 주문 → 차트 → 정보.
- 주문 작업: 매수 → 매도 → 정정/취소 → 미체결 → 잔고.
- 재생 속도: 정지 / 5분 / 15분 / 50분, 애니메이션 비율 0 / 1 / 3 / 10. 각 숫자는 현실 1.000초마다 흐르는 게임 분이다.
- 시간 정본 근거: SIMUL `game/market_clock.dart:31-38`은 기본 현실 1초=게임 5분과 고정 1초 주기를 정의하고, `stock_market_screen.dart:1190-1197`은 5/15/50분 및 0/1/3/10을, `:1411-1413`은 현실 1초 기준 툴팁을, `:2034-2035`는 그 고정 주기의 `Timer.periodic` 호출을 정의한다.
- Unity는 `Time.unscaledDeltaTime`을 `StockMarketRealtimeClock`에 누적한다. 매 1.000초마다 5/15/50분을 방출하고 프레임 드롭 때 여러 틱을 따라잡으며 1초 미만 잔여시간을 버리지 않는다. `Time.timeScale`과 무관하다.
- 애니메이션 비율은 화면 재생 속도만 바꾸며 정본 시장 상태는 분당 정확히 한 번만 갱신한다. 같은 seed·같은 분·같은 주문은 1/3/10에서 동일하다.
- 거래소 내부 호가 깊이는 매도 10 + 매수 10이며 화면은 매도 7 + 매수 7이다.
- 화면 순서는 높은 매도호가에서 최우선 매도호가, 최우선 매수호가에서 낮은 매수호가 순서다.
- 비어 있는 중앙 호가는 수량 0 표시 행일 뿐 체결 유동성이 아니다.
- 플레이어 미체결 주문은 외부 수량과 별도로 표시하며 가격 우선·시간 우선 FIFO를 따른다.
- 한 분 안에서 체결된 호가수량과 체결용량은 즉시 스냅샷에서 차감되어 다음 주문이 재사용할 수 없다.
- 현재가 외곽선, 같은 가격 반대편 이월, 일일 상하한, 호가 단위, 거래일/장 시간, 수수료·거래세, 주문 예약금과 체결 의미를 기존 C# 포트 규칙으로 처리한다.
- 모션 상수는 기본 144ms, 스윕 480ms, 단계 56~96ms, 마지막 유지 112ms, 정착 20ms, 최소 표시 36ms를 유지한다.

## 가로 배치

- 왼쪽: 1차 메뉴, 검색·필터, 실제 역사 상장 종목.
- 가운데 가변 폭: 종목 상세와 최근 체결.
- 오른쪽 고정 폭 1: 7+7 호가.
- 오른쪽 고정 폭 2: 주문·정정/취소·미체결·잔고.
- 기준 높이 1080, 최소 논리 폭 1600, 최대 논리 폭 3200이다. 16:9는 4열을 유지하고 울트라와이드는 가운데 작업 영역을 넓힌다.
- 960×540 미만에서는 주문·호가를 찌그러뜨리지 않고 최소 창 크기 안내와 F3 닫기만 표시한다.
- 종목 필터 행은 36px, 정렬 행은 36px이며 정렬 버튼 아래에서 `실제 역사 상장 종목` 제목까지 16px, 제목 아래 첫 목록 행까지 12px 이상을 확보한다. 제목은 32px, 목록 행은 66px 높이로 실제 폰트 메트릭을 수용한다.
- 긴 종목명은 한 줄 말줄임으로 제한하며 가격·등락률·종목코드 영역과 겹치지 않는다.

## 09:00 개장 정본

- 개장 준비 시간에는 주문 접수와 취소만 허용하고 체결 테이프·포지션·현금은 바뀌지 않는다.
- 09:00 경계에서 opening call auction을 정확히 한 번 처리한다. 같은 09:00 타임스탬프 재호출은 중복 체결하지 않는다.
- 09:00 이후에는 내부 10+10, 화면 7+7 호가와 가격·시간 우선 FIFO, 소진 잔량을 사용한다. 체결 테이프·차트·현재가는 같은 canonical snapshot을 읽는다.
- 08:59에서 5/15/50분 배속으로 09:00을 건너도 경계 이벤트를 먼저 처리하므로 시초가와 체결 결과가 같다.
- 실제 플레이어 기준: 08:59:59 주문 1건·현금/포지션/테이프 변화 0, 09:00:00 개장 처리 1회·개장 체결 2건·현재가/차트 21,100원, 09:00:01 중복 개장 0, 09:01 정규장 테이프 1건이다. 5/15/50분 시초가는 모두 21,100원이었다.

## 현재 런타임 연결

- F3 또는 게임 HUD의 `주식시장` 버튼으로 실제 플레이 중 연다.
- 종목 선택, 호가 클릭, 지정가/시장가 매수·매도, 일부/전체 체결, 미체결 등록, 예약금, 취소, 보유수량, 평균단가, 체결 테이프가 하나의 `StockMarketRuntimeSession` 상태를 함께 사용한다.
- 수량 단축키는 정본 10/20/50/100%이며 수수료, 시장가 체결용량, 매도 미체결 예약수량을 반영한다.
- 평균 매입가는 매수 수수료를 포함한다. 정정은 기존 주문과 예약을 해제한 뒤 수정 가격·잔여수량으로 새 FIFO 주문을 만든다.
- 홈 지표, 종목 목록, 차트, 호가, 최근 체결, 내 투자는 모두 같은 세션 분·호가 스냅샷을 읽는다. Presentation 계층에는 별도 `StableHash` 가격 경로가 없다.
- 내 투자는 세션 전체 보유·미체결·주문일지를 표시하고 관심종목은 세션 상태로 등록·필터링한다.
- 창이 열린 동안 플레이어 이동, 직접업무 상호작용, 카메라 추적/휠 줌 컴포넌트의 기존 `enabled` 값을 저장하고 끈다. F3 닫기, 닫기 버튼, 일시정지/메뉴 전환, 컴포넌트 비활성화·파괴 시 정확히 복원한다.
- 패널 실행 순서는 `-2000`이며 모든 마우스·키·스크롤 이벤트를 주식 컨트롤 처리 후 소비해 뒤쪽 IMGUI HUD 클릭 관통을 막는다.

## 회사 회계·저장 연결 코어

- 신규 `GameState.StockMarket`은 초기 미개설·예수금 0원이다. 창업자금 500만원을 자동 복사하지 않으므로 이중계상이 없다.
- `CompanyBrokerageTransferService`가 회사 현금→증권 예수금 입금과 증권 예수금→회사 현금 출금을 담당한다. 입금은 `차변 brokerage_account / 대변 cash`, 출금은 반대로 기존 `CompanyState` 원장에 균형 분개한다.
- 0원·음수, 회사 현금 초과, 중복 거래 ID를 거절한다. 장중 입출금은 허용하지만 매수 미체결 예약금은 `AvailableBrokerageCash`에서 제외되어 출금할 수 없다.
- `StockMarketSessionStateDto`는 예수금·전 종목 포지션과 수수료 포함 평균원가·미체결·내 체결·주문일지·관심종목·FIFO 시퀀스에 더해 거래일, 시장 분, 실시간 잔여초, 배속, 09:00 개장 처리 여부/횟수와 canonical 갱신 횟수를 보존한다.
- 공용 Save V5에 선택적 `stockMarket` 필드를 추가했다. 구형 V1~V5 저장에 이 필드가 없으면 미개설·0원 상태로 올리고, 새 저장은 위 상태를 왕복한다. 기존 V5 번호를 유지해 다른 진행 중 저장 작업과의 스키마 충돌을 피했다.
- `StockMarketFullscreenPanel`은 50,000원 격리 fixture를 사용하지 않는다. 실제 `PrototypeBootstrap.State`의 회사 현금과 증권 예수금을 표시하고 입출금 UI를 제공하며, 닫기·비활성화·파괴·프레임 갱신 경계에서 `StockMarketGameStateBridge`로 자동 flush/load한다.
- 같은 거래일 복원은 실시간 잔여초, 배속, FIFO sequence·queue-ahead, 세션·개장 멱등성 상태를 포함한 전체 세션을 이어간다. 날짜가 바뀌면 현재 비거래 종목의 보유·내 체결·주문일지·관심종목은 보존하고 해당 종목의 미체결만 결정적으로 취소해 예약금을 해제한다.
- 역사 등록부에 존재하는 비거래 종목 ID와 손상 저장의 미지 ID를 구분한다. 알려진 과거 종목은 승계하지만 포지션·미체결·체결·관심종목의 미지 ID는 복원을 거절한다.

## QA

- 순수 규칙 검증: 1280×720, 1600×900, 1920×1080, 2560×1080, 3440×1440, 1920×1200의 캔버스 내부·무겹침 검증.
- 실제 Windows 플레이어 캡처: 1280×720, 1920×1080, 3440×1080, 안전 안내 568×843.
- 기존 실제 캡처는 열기 → 이동/직접업무/카메라 비활성 → 닫기 복원 → 메뉴 전환 복원 → 다시 열기 → 뒤 HUD `+1시간` 좌표 실제 클릭 소비 → 마우스 휠 뒤 카메라 줌 불변 → 시장가 1주 체결 → 스크린샷 순으로 실행했다. 현재 런타임은 해당 격리 계좌 대신 실제 회사/증권계좌를 사용한다.
- 네 실제 캡처 모두 `MaplestoryLight/MaplestoryBold + PretendardVariable fallback`, ImageGen 스킨, 글리프/텍스트 rect 검사, 클릭·휠 모달 차단, 09:00 표 검증을 통과했다. 1280×720과 1920×1080에서 `거래대금/상승/하락/이름`, `실제 역사 상장 종목`, `핸디소프트`, 코드, 7+7 호가와 최근 체결의 클리핑은 0이다.
- 현실 시간 실측: 정지 12.015초에 +0분, 5분 모드 12.016초에 +55분(프레임 1회 허용오차 -5분), 15분 모드 12.016초에 +180분(`timeScale=0.25`), 50분 모드 12.016초에 +600분이다. 2.4초 프레임 catch-up은 +10분과 잔여 0.4초, 다음 0.6초는 +5분으로 잔여시간 보존을 통과했다.
- 회사 회계·저장 순수 회귀는 500만원에서 20만원 입금, 음수·초과·중복 차단, 예약금 초과 출금 차단, 수수료 포함 평균원가, 1만원 출금, 입출금 균형 분개, 현금·포지션·미체결·내 체결·시장 분·개장 횟수·실시간 잔여 0.4초 왕복을 통과했다.
- 상장집합 변경 회귀는 비거래 종목 보유·내 체결·일지·관심종목 보존, 해당 미체결 1건 취소와 예약금 해제, 현재 상장 종목 미체결 보존, 미지 자산 ID 거절을 통과했다.
- 닫기/저장/재개 회귀는 0.4초 residual 뒤 0.6초를 더했을 때 연속 실행과 재개 실행 모두 정확히 5분을 진행하고, tape 순서와 미체결 주문 ID·FIFO sequence·잔량·queue-ahead가 동일함을 확인했다.
- 3440×1440 창은 현재 QA 장비의 1080 높이 작업영역 제한 때문에 실제 창 생성은 불가했으며, 해당 해상도는 순수 레이아웃 검증으로 통과했다.
