# 가족 보행 에셋 제작 가드레일

> 2026-08-19 현재 이 문서는 삭제된 가족 4명 생성 파이프라인의 실패 provenance다. 언급된
> ArtSources/writer/gate는 제거됐으며 실행하면 안 된다. 현재 사람 승인 권한은 CANON의
> `FC-PLAYER-EAST-CONTACT-V1`, `FC-PLAYER-SOUTH-CONTACT-V1`이다. north/west와 diagonal cardinal mapping은
> D3D11 실행 게이트 PASS, 사용자 최종 화면 승인 대기 후보다.

계약 ID: `FC-WALK-GUARDRAIL-V1`

이 문서는 가족 4명의 보행 프레임을 만들거나 고치기 전에 반드시 읽는 정본이다. 프롬프트,
원본 가져오기, 자동 보정, Unity 빌드 중 하나라도 시작하기 전에 작업 로그에 위 계약 ID를 남긴다.
이 문서의 조건 하나라도 직접 확인하지 못한 후보는 실패다. 픽셀 변화율, 파일 수, FAST_QA 성공으로
대체 판정하지 않는다.

## 사용자가 요구한 화면 결과

- 가족은 타일 중심에서 다음 타일 중심으로 이동한다.
- 이동은 화면에서 실제 진행하는 방향을 몸 전체가 먼저 본 뒤 시작한다.
- 한 주기는 왼발과 오른발이 한 번씩 앞으로 나오는 실제 두 걸음이다.
- 발을 낮게 옮기는 차분한 사무실 보행이어야 한다. 뛰기, 행진, 깡충거림, 옆으로 꺾인 무릎,
  과도한 다리 벌림은 모두 실패다.
- 방향이 바뀌어도 머리 크기, 몸통 폭, 골반 높이, 다리 길이, 신발 높이가 갑자기 달라지지 않는다.
- 바지·치마·다리 주변의 반투명 잔상, 크로마 조각, 끊긴 외곽선, 다른 포즈 조각이 0이어야 한다.
- 같은 셀에서 좌우를 한 번씩 보는 중복 pivot, 이동 중 반대 방향 몸, 옆걸음 프레임이 0이어야 한다.

## 오늘 반복한 실패와 다시 하면 안 되는 이유

1. **그림 생성 모델의 여섯 칸 설명만 믿었다.**
   모델은 `왼발 접지→오른발 접지`라고 명시해도 0번과 3번에 같은 신발을 다시 그렸다. 칸 위에 붙인
   `L CONTACT`, `R CONTACT` 글자는 해부학적 증거가 아니다.
2. **프레임 차이율을 두 발 교대 판정으로 오인했다.**
   옷, 팔, 머리카락이 달라지면 하체 변화율도 통과할 수 있다. 기존 `pixel0<->3`, `unique=6/6`,
   `pass-swap` 수치는 어느 해부학적 발이 움직였는지 증명하지 못했다.
3. **색상 정체성 없이 발을 눈으로만 판정했다.**
   같은 색 바지와 신발은 같은 발 반복을 숨긴다. 생성·검수 원본에는 해부학적 왼다리와 오른다리의
   영구 표식이 필요하다.
4. **서로 다른 세대의 그림을 런타임에서 섞었다.**
   V4 직교 방향, V7 대각 방향, 별도 `LocomotionTransitionsV1` 시작·정지·회전 그림은 머리·모자·허리·
   바지 실루엣이 서로 다르다. 소년은 전환 순간 빨간 모자까지 사라졌다. 이 교체가 사용자가 본
   투명 잔상과 바지 깨짐처럼 읽혔다.
5. **보폭이 큰 그림을 '두 발이 보인다'는 이유로 채택했다.**
   발 교대가 맞아도 접지발 간격, 무릎 높이, 골반 흔들림이 크면 뛰거나 촐싹거리는 동작이다.
6. **무릎을 옆으로 접은 기계 변형을 자연 보행으로 취급했다.**
   관절점이나 하체 반사 결과는 반드시 사람이 볼 수 있는 연속 재생으로 확인해야 한다. 숫자상 바닥선이
   맞아도 다리가 옆으로 꺾이면 즉시 실패다.
7. **에셋을 바꾼 뒤 이전 EXE 창을 그대로 보여 줬다.**
   소스 변경, Unity import, 새 빌드, 실행 파일 SHA-256 확인을 마치기 전에는 사용자에게 '교체됐다'고
   말하지 않는다. 현재 창 PID와 실행 경로가 새 후보인지 확인한다.
8. **실제 normal 새 게임보다 생성 시트와 강제 QA를 먼저 믿었다.**
   최종 판정은 빈 사무실 normal 새 게임의 실제 이동이다. 강제 방향·강제 프레임 QA는 보조 증거일 뿐이다.

## 해부학적 6프레임 계약

| 프레임 | 고정 의미 | 접지/이동 조건 |
| --- | --- | --- |
| 0 | 왼발 접지 | 해부학적 왼발이 짧게 앞, 오른발은 짧게 뒤 |
| 1 | 왼발 지지 | 왼발은 골반 아래 접지, 오른발은 바닥 가까이 회수 |
| 2 | 오른발 통과 | 오른발이 왼발 옆을 낮게 통과 |
| 3 | 오른발 접지 | 해부학적 오른발이 짧게 앞, 왼발은 짧게 뒤 |
| 4 | 오른발 지지 | 오른발은 골반 아래 접지, 왼발은 바닥 가까이 회수 |
| 5 | 왼발 통과 | 왼발이 오른발 옆을 낮게 통과 |

- 생성 검수용 원본에서는 해부학적 왼다리를 청록, 오른다리를 자홍으로 hip-to-toe 연속 표식한다.
- 표식은 프레임 사이에서 절대 바뀌지 않는다. 최종 팔레트로 바꾸기 전에 의미 검증을 끝낸다.
- 이미지 생성 모델에는 첫 반주기 0·1·2의 자연스러운 모양과 캐릭터 정체성만 맡긴다.
- 3·4·5의 반대 발은 0·1·2의 검증된 하체를 골반 축 기준으로 결정론적으로 반사해 만든다. 생성 모델이
  그린 두 번째 반주기를 발 교대 증거로 사용하지 않는다.
- 반사 후에도 상체는 해당 시점의 반대 팔 흔들림을 사용하되, 얼굴·머리·옷·카메라 방향은 반사하지 않는다.
- 왼발·오른발 마스크가 분리되지 않거나 골반 봉합선에 구멍이 생기면 자동 보정하지 말고 후보를 폐기한다.

## 차분한 보폭과 실루엣 기준

- 0·3 접지 포즈의 앞뒤 신발 중심 간격은 머리 폭의 0.55배 이하여야 한다.
- 2·5 통과발은 발목 옆을 지나며 발바닥 상승이 머리 높이의 0.20배 이하여야 한다.
- 6프레임의 머리 꼭대기·골반 기준선 수직 변화는 정규화된 256px 셀에서 2px 이하여야 한다.
- 무릎은 진행축으로 굽고 좌우 외측으로 꺾이지 않는다. 두 정강이가 X자처럼 교차하면 실패다.
- 전 프레임 가족별 키와 바닥선은 동일해야 한다. 신발 밑 8px 투명 여백을 유지한다.
- 불투명도는 0 또는 255만 허용한다. 주 실루엣 밖 연결 조각, 크로마, 체크무늬, 그림자, 잔상이 0이어야 한다.
- 정지·pivot·출발·정지 전환용 별도 캐릭터 그림을 섞지 않는다. 필요하면 같은 승인 보행 프레임에서
  결정론적으로 파생하거나 전환 그림을 사용하지 않는다.

## 기계 게이트: 두 걸음 증명 (필수, 다른 모든 검증보다 먼저)

계약 ID: `FC-WALK-TWOSTEP-GATE-V1`

지금까지의 게이트는 전부 **변화율**을 재서, 같은 발이 여섯 프레임 내내 앞에 있어도 옷·팔·머리카락이
바뀌면 통과했다. 이 게이트는 변화율을 재지 않는다. 한 발 절뚝임이 절대 만족할 수 없는 두 가지만 묻는다.

```powershell
.\Tools\Verify-FamilyWalkTwoStep.ps1                      # 런타임 32행
.\Tools\Verify-FamilyWalkTwoStep.ps1 -Source artsources    # 추적 소스 32행
.\Tools\Verify-FamilyWalkTwoStep.ps1 -Member father -Direction east
.\Tools\Verify-FamilyWalkTwoStep.ps1 -SelfTest              # 게이트 자체 검증

# 후보 폴더 판정: 출하본 + 표식 사본을 함께 검사한다
.\Tools\Verify-FamilyWalkTwoStep.ps1 -Member father -FrameDirectory <후보> -MarkerDirectory <후보>\markers
.\Tools\Verify-FamilyWalkTwoStep.ps1 -Member father -FrameDirectory <후보>\markers -MarkerCopy
```

PowerShell + System.Drawing만 쓴다. Python·PIL·numpy가 없어도 돌아가므로 환경을 이유로 건너뛸 수 없다.

`-SelfTest`는 게이트를 세 방향으로 증명한다. father/east 기준이다.

1. 계약대로 **하체만** 반사해 3·4·5를 합성한 행 → 반드시 PASS (`mirror=0`, `head-stable=ok`)
2. 0·1·2를 그대로 3·4·5에 복제한 **합성 한 발 반복 행** → 반드시 FAIL (`MIRROR-FAIL`, `LEAD-FAIL`)
3. **프레임 전체를 반전한 치트 행** → 반드시 FAIL (`head-stable=HEAD-MIRRORED`)

음성 대조군을 현재 출하 행에 의존시키면 출하 행을 고친 순간 자기검증이 실패하므로, 2번은 매 실행 때
정본 0·1·2로부터 별도 임시 폴더에 합성한다. 3번 치트는 실측에서 `0<->3 mirror=0`,
`lead-swap=ok`로 다리 조건 두 개를 완벽히 통과한다. 불변조건 3
없이는 그대로 승인됐을 후보다. 자기검증이 PASS가 아니면 게이트 결과를 인용하지 않는다. 항상 실패하는
검사기도, 치트를 통과시키는 검사기도 증거가 아니다.

### 게이트의 권한과 한계 — 비대칭이다

이 게이트는 실루엣 반사와 신발 군집의 화면상 좌우를 보는 **구조** 검사다. 따라서 권한은 한 방향으로만
절대적이다.

- **FAIL이면 후보는 죽는다.** 사람 눈, GIF, 변화율, FAST_QA, "그래도 자연스럽다"로 뒤집지 않는다.
  지금까지 5시간을 태운 실패 방식은 정확히 그 반대였다. 사람 눈과 변화율이 PASS라고 해서 한 발
  절뚝임이 통과했다.
- **PASS는 필요조건일 뿐 충분조건이 아니다.** 통과한 뒤에 아래를 여전히 사람이 확인한다.

게이트가 판정하지 못하는 것을 명시한다.

1. **해부학적 발 정체성.** 실루엣만 보므로 "이게 해부학적 왼발"이라고 말할 수 없다. 청록/자홍 hip-to-toe
   영구 표식은 여전히 필요하다. 표식이 생기면 게이트는 무력해지는 게 아니라 **강해진다**: 0과 3의 앞발
   표식 색이 달라야 한다는 네 번째 불변조건을 추가하면 이 구멍이 완전히 닫힌다.
2. **근/원 다리의 앞뒤 겹침.** 3/4 시점에서 하체를 반사하면 가까운 다리와 먼 다리의 가림 순서가 바뀔 수
   있다. 실루엣이 같아도 깊이가 뒤집힌 그림은 게이트를 통과한다.
3. **보폭·무릎 방향·발 들림·골반 흔들림.** 이 문서의 0.55배·0.20배·2px 계약은 아직 산문이다. 게이트는
   그 숫자를 재지 않는다.
4. **south/north 행의 LEAD-SWAP.** 정면·배면에서는 두 신발이 붙어 `unmeasurable`이 된다. 그 행은
   불변조건 1·3으로만 검증되므로 사람 확인 비중이 더 크다.
5. **런타임 재생.** 프레임 0~5가 실제로 순서대로, 맞는 방향 행으로 재생되는지는 별개 문제다.

### 불변조건 1 — PELVIS-MIRROR

프레임 3·4·5의 **하체**는 0·1·2 하체의 골반축 반사여야 한다. 반사로 만들었다면 반사 거리는 구조적으로
0에 가깝다. 게이트는 두 거리를 함께 출력한다.

- `mirror` = 프레임 B 하체를 골반축으로 반사해 A와 비교한 XOR 면적
- `same` = 반사하지 않고 비교한 XOR 면적
- 통과 조건: `mirror <= same * 0.5` **그리고** `mirror <= 하체면적 * 0.20`

`mirror`가 `same`보다 크면 프레임 3은 프레임 0의 **복사본**이라는 뜻이다. 즉 두 번째 반주기가 없다.
상체는 비교 범위 밖(캐릭터별 `V5_LOWER_BODY_START` 아래)이므로 셔츠·팔·머리로 점수를 살 수 없다.

### 불변조건 2 — LEAD-SWAP

두 접지 프레임 0과 3에서 **앞으로 나온 신발이 골반축 반대편**에 있어야 한다. 이것이 "왼발이 한 번,
오른발이 한 번 앞에 나온다"의 문자 그대로의 진술이다. 두 신발이 붙어 분리되지 않으면
`unmeasurable`로 실패 처리한다. 접지 프레임에서 두 발이 분리되지 않는 것 자체가 접지 포즈가 아니라는
증거다.

### 불변조건 3 — HEAD-STABLE

불변조건 1·2를 공짜로 통과하는 치트가 정확히 하나 있다. **프레임 전체를 좌우 반전**하는 것이다. 그러면
하체 반사 거리가 0이고 앞발도 반대편으로 가지만, 얼굴·머리·옷·카메라 방향까지 뒤집혀 이 문서가 금지한
결과가 되고 플레이어는 즉시 알아본다. 그래서 머리 밴드(실루엣 상단 22%)는 **반사되지 않아야** 한다.

- 통과 조건: `headMirror >= headSame * 0.8`
- `head-stable=HEAD-MIRRORED`이면 하체만 반사한 게 아니라 프레임을 통째로 뒤집은 후보다.

### 불변조건 4 — MARKER-CLEAN / 표식 사본 소유권

표식은 **출하 픽셀에 절대 닿지 않는다.** 지금까지 프로브가 반복 폐기된 이유가 이것이다. 출하 아트에
청록·자홍을 칠하고 다시 빼내려 했고, 캐릭터 자기 팔레트가 표식 색과 겹쳐서 깨끗해질 수가 없었다.

- **출하본**: 표식 없는 원본. 골반 아래에 청록·자홍 계열 픽셀이 **0개**여야 한다.
- **표식 사본**: 같은 몸에 표식만 칠한 별도 산출물. 청록·자홍이 각각 존재해야 한다(`-MarkerCopy`).
- **동일 알파 실루엣**: 두 산출물의 알파가 프레임마다 픽셀 단위로 같아야 한다(`-MarkerDirectory`).
  다른 몸에 칠한 표식은 출하본에 대해 아무것도 증명하지 못한다.

같은 `-MarkerDirectory`로 해부학 표식 교대(0의 앞발 색 ≠ 3의 앞발 색, 2와 5의 통과발 색 교대)까지
함께 판정한다. 표식이 생기면 게이트는 무력해지는 게 아니라 강해진다.

잔류 판정은 **절대 hue 밴드로 하지 않는다.** 청록/자홍 hue를 그냥 세면 아빠 셔츠(`rgb 44,79,83`)에서
전신 155,807픽셀, 엄마 청록 치마에서 하체 18,511픽셀이 거짓 실패한다. 그래서 표식 색은 **두 사본이 실제로
다른 픽셀에서 학습**한다. 즉 "표식 패스가 새로 칠한 색"만 잔류로 센다. 표식 사본이 없으면 이 검사는
판정하지 않고 침묵한다. 추측하지 않는다.

#### 알려진 사각지대 — 어두운 외곽 잔류

`father-contact-separation-probe-53`은 다리 불변조건 1·2·3과 표식 교대, 실루엣 동일성을 **모두 통과한다**.

```
marker-clean=ok (0 px of 2 marker colours) | marker-silhouette=ok (identical alpha)
anatomy-markers=ok (contact 0=magenta 3=cyan; passing 2=magenta 5=cyan)
```

그런데 사람 눈에는 바지 양옆에 표식의 **어두운 외곽**이 남아 있다. 실측하면 하체에 청록·자홍 계열
8,154픽셀이 48/48 프레임에 있는데(`rgb 99,16,76` / `19,110,132`), 이 값들은 표식 원색에서 tolerance
밖으로 멀어서 색 학습 방식으로는 잡히지 않는다. 원색 기준은 거짓 실패가 0이지만 어두운 잔류를 놓치고,
hue 밴드 기준은 잔류를 잡지만 셔츠·치마에서 거짓 실패한다. **현재 어느 자동 기준도 이 둘을 동시에
만족시키지 못한다.**

그래서 이 사각지대는 검사를 더 정교하게 만들어 닫지 않는다. **애초에 출하 픽셀에 칠하지 않으면 존재할 수
없는 실패**다. 표식을 칠하고 다시 빼내는 파이프라인을 유지하는 동안에는 이 항목만 사람 눈이 필수다.
칠하지 않는 구조로 바꾸면 검사 자체가 불필요해진다.

### 생성 예산 — 캐릭터당 15패널. 그 이상 생성하지 않는다

이미지 모델은 동일 인물·동일 키·동일 팔레트를 여러 장에 걸쳐 유지하지 못한다. 그래서 모델에 맡기는
장수를 구조적으로 줄인다.

- 미러 쌍은 3개다: `east↔west`, `northeast↔northwest`, `southeast↔southwest`.
  `build_family_walk_half_cycles_v2.py`의 `MIRROR_PAIRS`가 이미 이 등가성을 검증한다.
- `north`와 `south`는 자기 자신이 미러이므로 **둘 다 원본이 필요하다**.
- 따라서 원본 방향은 `south, southeast, east, northeast, north` **5방향**이다.
- 각 방향은 첫 반주기 3패널만 생성한다. 3·4·5는 반사로 만든다.

**5방향 × 3패널 = 캐릭터당 15패널.** 48장을 생성하지 않는다. 생성 횟수가 줄면 인물 드리프트와 재생성
라운드가 함께 줄어든다.

### 반주기 3패널의 합격 기준 — 발 교대는 여기서 판정하지 않는다

반주기(0·1·2)는 **왼발 접지 → 왼발 지지 → 오른발 통과**, 즉 한 걸음이다. 세 패널에서 같은 다리가 앞에
있는 것이 계약이며, 앞발이 바뀌면 오히려 위반이다. 발 교대는 0↔3에서 일어나고 그것은 생성이 아니라
반사가 만든다.

| 검사 | 3패널 반주기 | 조립된 6프레임 행 |
| --- | --- | --- |
| 앞발 교대(LEAD-SWAP) | **판정하지 않음** | 필수 |
| 하체 반사(PELVIS-MIRROR) | 판정하지 않음 | 필수 |
| 머리 비반사(HEAD-STABLE) | 판정하지 않음 | 필수 |
| 보폭 ≤ 머리폭 0.55배 | 필수 | 필수 |
| 무릎이 진행축으로만 굽음 | 필수 | 필수 |
| 두 다리 표식 분리 | 필수(표식 사본) | 필수(표식 사본) |
| 바닥선·키 고정, hard alpha | 필수 | 필수 |

"한쪽 다리만 움직인다"를 반주기 불합격 사유로 쓰면 영원히 끝나지 않는다. 반주기는 위 표의 오른쪽 열이
아니라 왼쪽 열로만 판정한다.

### 2026-08-17 역사 기준선 — 당시 아트는 32행 전부 실패

이 게이트를 도입한 시점의 런타임 아트 실측이다. 이후 후보는 이 수치보다 나아진 것을 숫자로 보여야 한다.

```
FAMILY_WALK_TWO_STEP_GATE: FAIL | contract=FC-WALK-TWOSTEP-GATE-V1 source=runtime rows=32 failed=32
```

대표 행:

| 행 | 0↔3 mirror | 0↔3 same | LEAD-SWAP |
| --- | ---: | ---: | --- |
| father east | 1605 | 1113 | FAIL — 0과 3이 같은 쪽 발로 접지 |
| father west | 1579 | 1115 | FAIL — 같은 쪽 발 |
| player east | 2824 | 2248 | FAIL — 같은 쪽 발 |
| player northeast | 870 | 168 | 측정 불가(두 발 붙음) |
| mother southeast | 2374 | 1126 | FAIL — 같은 쪽 발 |
| older_sister east | 1168 | 1634 | ok(발은 교대) — 그러나 하체가 반사 관계 아님 |

`same`이 `mirror`보다 작은 행은 프레임 3이 프레임 0의 복사본에 가깝다는 뜻이다. `player northeast`의
`same=168`은 사실상 같은 그림이다.

### [퇴역 이력] 파이프라인이 계약을 폐기했던 지점과 2026-08-18 당시 해소

2026-08-17 당시 `Tools/build_family_walk_half_cycles_v2.py` 첫 주석은 다음과 같았다.

> "V6 replaces the rejected reflected-lower-body cycle: ... exchange contact/support/pass roles
> **without reflecting** or recolouring one generated foot."

이 문서의 6프레임 계약은 반대로 **반사를 요구한다**. 당시 같은 1,949줄 파일에 V5 반사·V6 joint
rig·V7 색 정체성·raw strip import 세대와 서로 배타적인 CLI 모드가 겹쳐 있었다. 따라서 추적 원화가
마지막 수동 실행 모드에 따라 달라졌고, 한 번 고친 뒤 다른 import에서 되돌아왔다.

2026-08-18 당시 이 문제를 해소했다. 당시 builder는 `ArtSources/FamilyWalkHalfCyclesV2`의 identity-locked
출하 source와 별도 marker review copy만 읽는 단일 source→runtime publish 경로다. 구형
`--bootstrap-existing`, `--import-v4-masters`, `--import-v6-joint-rig`, `--import-v7-color-identity`,
`--import-strip`, `--rotate-source`, `--normalize-sources` 모드는 제거했다. `--write`는 source/marker
32행의 해부학 표식과 두 걸음 게이트가 모두 PASS한 뒤에만 실행된다. 어떤 세대 이름이나 마지막 수동
import도 추적 원화를 바꿀 수 없다.

### 2026-08-18 현재 추적 후보 — 32행 PASS

identity-locked candidate 61을 추적 source와 runtime으로 채택했다. 출하본에는 표식이 한 번도 닿지
않고, 표식은 byte-identical alpha를 가진 별도 사본에만 존재한다. 방향별 canonical identity anchor가
머리·얼굴·몸통·골반·옷 길이·다리·신발 크기의 기준이다. candidate 62 재현 시도는 이 게이트에서
실패했기 때문에 원화·runtime으로 승격하지 않았다.

```text
FAMILY_WALK_TWO_STEP_GATE_SELFTEST: PASS | reflected row accepted, synthetic one-leg row rejected, whole-frame mirror rejected
FAMILY_WALK_ANATOMY_MARKER_GATE: PASS | contract=FC-WALK-TWOSTEP-GATE-V1 source=artsources rows=32
FAMILY_WALK_TWO_STEP_GATE: PASS | contract=FC-WALK-TWOSTEP-GATE-V1 source=artsources rows=32
FAMILY_WALK_RUNTIME_STATIC_ROWS: passed=32 total=32
```

이 현재 PASS는 2026-08-17 실패 기준선을 지우지 않는다. 기준선은 게이트가 실제 결함을 잡았다는 역사
대조군이고, candidate 61은 이후 사람 시트/GIF, identity 비교, runtime byte 일치와 실제 normal EXE를

## 채택 전 필수 검증 순서

0. `Tools\Verify-FamilyWalkTwoStep.ps1`이 32행 모두 PASS인지 먼저 확인한다. 여기서 실패한 후보는

2. 네 가족 × 실제 타일 이동 화면 방향 SW/SE/NE/NW를 6칸 시트와 8fps 이하 GIF로 사람이 확인한다.
3. 바지·치마·신발 주변 알파와 연결 성분을 검사한다.
4. 동일 가족의 네 방향 실루엣 높이·몸통 폭·골반 높이를 비교한다.
