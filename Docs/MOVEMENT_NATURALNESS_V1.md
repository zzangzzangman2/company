# MOVEMENT NATURALNESS V1 — 움직임 자연스러움

작성: 2026-08-11 / Claude
성격: **감사 결과 + 요청서**. 정본이 아니다.
전제: 코덱스가 지금 이 영역을 작업 중이다. **중복 요청을 피하려고 먼저 있는 것부터 확인했다.**

## 0. 결론

> **코덱스가 이미 대부분 만들어 놨다. 검증된 빈 곳은 "문 앞 순서"뿐이다.**

"움직임이 자연스럽지 않다"는 느낌의 원인은 이동 로직이 아니라
**앞서 잡은 캐릭터 크기 문제**일 가능성이 크다. 화면의 5.8%짜리 캐릭터는
아무리 잘 움직여도 개미가 꿈틀거리는 것으로 보인다.

그래서 순서는 이렇다.

1. 캐릭터 크기 정상화 (`OFFICE_VIEW_FIX_REQUEST.md`) — 타일 씬에서는 이미 해결됨
2. 메인 흐름을 타일로 교체 — 그때 이동 계층도 같이 승계
3. **그 다음에** 남은 자연스러움 항목을 본다

## 2. 검증된 빈 곳 — 문 앞 순서 보장

`Queue`를 전 코드에서 검색한 결과 **사무실 이동 관련 대기열이 하나도 없다.**
검색에 걸린 모든 `Queue`는 주식 호가창(`MarketOrderBookReplay`)과 이벤트 큐다.

### 지금 구조로 무엇이 부족한가

현재 회피는 **쌍 단위**다. A와 B가 서로 밀려나지 않게만 한다.
그런데 문은 **폭이 한 명**이고 **통과 순서**가 있어야 한다.

세 명이 동시에 퇴실하면 지금 로직은 이렇게 된다.

- 셋 다 문 앞으로 간다
- 셋 다 서로를 피하려 한다
- 반경이 겹쳐 `IsAgentMovementCollisionFree`가 계속 false
- `stuckSeconds`가 올라가 재계획 → 다시 문 앞으로 → 반복

즉 **비벼진다.** 회피만으로는 순서가 정해지지 않는다.

### 요청 — 문 통과권(Doorway Token)

가장 단순하고 확실한 방식이다.

```
문마다 통과권 1장.
- 통과권을 가진 에이전트만 문 칸에 진입할 수 있다
- 통과권은 문을 완전히 지나거나(Despawn) 취소될 때 반납된다
- 나머지는 문 앞 대기 지점에 줄을 서서 기다린다
- 대기 순서는 도착 순서 (같으면 AgentId 사전순) — 결정론 유지
- 통과권 보유 시간 상한을 둔다. 넘으면 강제 반납해 교착을 막는다
```

**대기 지점을 문 앞 한 곳으로 두지 말고 줄 형태로 2~3칸 두는 게 좋다.**
한 지점에 모이면 대기 중에 또 서로 밀어낸다.

### 어디에 두어야 하나

`Simulation/Navigation/OfficeNavigationMotionRules.cs`가 이미 순수 C#이므로
**통과권 규칙도 그 옆 순수 계층**에 두는 것이 프로젝트 규칙과 맞는다.

```
Simulation/Navigation/OfficeDoorwayQueueRules.cs   (순수 규칙, 결정론)
Presentation.Unity/...                            (토큰 획득·반납 배선)
```

결정론이 중요하다. `MultiSeedAutonomyValidation`이 이미 다중 시드를 검사하므로
**같은 시드에서 같은 통과 순서**가 나와야 한다.

## 3. 자연스러움 체크리스트

타이쿤 사무실이 "살아 있다"고 느껴지는 조건을 항목화했다. 현재 상태를 함께 적는다.

| # | 항목 | 상태 |
| --- | --- | --- |
| 1 | 캐릭터가 서로 겹치지 않는다 | **있음** |
| 2 | 이미 겹쳤을 때 빠져나온다 | **있음** |
| 3 | 마주치면 한쪽이 양보한다 | **있음** |
| 4 | 막히면 다른 길을 찾는다 | **있음** |
| 5 | 가구를 뚫지 않는다 | **있음** (하위칸 프로파일) |
| 6 | 출발·정지가 부드럽다 | **있음** (locomotion transitions) |
| 7 | 앉아서 하는 동작이 있다 | **있음** (micro action) |
| 8 | **문을 순서대로 지난다** | **없음** ← 2장 |
| 9 | **서 있을 때 가만히 있지 않는다** | **확인 필요.** Idle 참조는 있으나 정지 중 동작 유무 미확인 |
| 10 | 같은 목표를 여럿이 노리지 않는다 | 좌석은 claim 있음. **프린터·정수기 등 공용 지점은 확인 필요** |
| 11 | 캐릭터가 알아볼 만한 크기다 | **메인 흐름은 아님** (5.8%). 타일 씬은 정상 (14.8~17.3%) |
| 12 | 발이 바닥에 붙어 있다 | 타일 씬에서 정렬 검증됨 |

**8·9·10만 남았고, 11이 체감을 가장 크게 바꾼다.**

### 9번과 10번이 왜 자연스러움에 중요한가

**9. 정지 중 동작**: 사람이 완전히 멈춰 있으면 즉시 인형처럼 보인다.
2~5초마다 아주 작은 동작 하나만 있어도 살아 보인다.
2000년 사무실이면 서류 넘기기, 시계 보기, 목 돌리기, 모니터 쪽으로 몸 기울이기.

**10. 목표 경쟁**: 두 명이 같은 프린터로 걸어가면 한 명은 헛걸음한다.
헛걸음 자체는 사람 같지만, **매번** 그러면 바보처럼 보인다.
좌석에는 이미 claim이 있으니 **공용 지점에도 같은 claim을 적용**하면 된다.

## 4. 코덱스와 겹치지 않게 내가 할 수 있는 것

2·3장은 전부 코덱스의 현재 작업 영역이다. 내가 손대면 충돌한다.
대신 **겹치지 않고 도움이 되는 것**은 측정이다.

### 제안: 자연스러움 자동 측정 QA

"자연스럽다"를 눈대중이 아니라 수치로 만든다. Editor 전용이고 읽기만 하므로 충돌하지 않는다.

| 지표 | 측정 방법 | 나쁨 판정 |
| --- | --- | --- |
| **겹침 시간 비율** | 매 프레임 모든 쌍의 거리 < 반경합인 시간 / 전체 시간 | 1% 초과 |
| **최대 동시 겹침 인원** | 같은 프레임에 겹친 최대 인원 | 3명 이상 |
| **정체 시간** | 속도 ≈ 0인데 목적지 미도달인 시간 | 한 번에 3초 초과 |
| **재계획 횟수** | `shouldReplan` 발생 횟수 / 분 | 분당 2회 초과 |
| **문 통과 간격** | 연속 통과자 사이 시간차 | 0.2초 미만 (= 동시 통과) |
| **경로 낭비율** | 실제 이동 거리 / 최단 거리 | 1.6 초과 |
| **정지 중 무동작 시간** | 멈춘 상태로 동작 없이 지난 시간 | 5초 초과 |

이 표가 있으면 코덱스가 파라미터를 만질 때 **좋아졌는지 나빠졌는지**를 바로 안다.
지금은 "느낌"으로만 판단하고 있어서 조정이 왔다 갔다 할 수 있다.

**출력**: `Artifacts/OfficeNaturalnessQa/naturalness-30s.txt` + 캡처 몇 장.
기존 `CharacterOfficeRuntimeQa`의 PLAY_SNAPSHOT 형식을 따라 붙이면 된다.

내가 만들 파일은 `Assets/FamilyCompany/Editor/OfficeNaturalnessQa.cs` 하나이고,
런타임 코드를 **수정하지 않고 읽기만** 한다. 충돌 위험이 없다.
