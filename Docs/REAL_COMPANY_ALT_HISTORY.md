# REAL COMPANY ALTERNATE HISTORY

## 목적

실제 회사의 2000~2026년 역사를 기준선으로 제공하되, 플레이어와 경쟁 AI의 행동이 원인을 바꾸면 결과도 달라지는 시뮬레이션을 만든다.

## 세 개의 상태층

### 1. HistoricalBaseline

검증된 회사 정보, 이름 변경, 상장, 제품군 전환, 합병, 분사, 파산과 거시 사건의 읽기 전용 기준선이다. 저장 게임에 의해 수정하지 않는다.

### 2. WorldState

현재 회차에서 실제로 존재하는 회사, 소유관계, 현금, 부채, 가치, 직원, 기술·IP, 브랜드, 시장 점유율, 상장과 지급능력 상태다.

### 3. DivergenceLog

기준 역사와 달라진 사건, 원인 행위자, 발생 시각, 취소·지연·대체된 원래 사건을 기록한다. 뉴스, 연감, 저장 디버깅과 엔딩에 사용한다.

## 실제 이름과 내부 ID

- `companyId`는 영구 불변이다. 회사명이 바뀌어도 저장과 참조는 같은 ID를 사용한다.
- 날짜별 법인명과 통용명은 `nameHistory` 배열에 저장한다.
- 인수·분사·합병은 `predecessorIds`, `successorIds`, 소유관계 이벤트로 표현한다.
- 개발 중 `debugDisplayName`은 실제 회사명을 사용한다.
- 향후 이름을 바꿀 때는 `releaseNameMap`만 교체하고 코드와 저장 ID는 바꾸지 않는다.
- 로고, 트레이드 드레스, 광고물은 실제 것을 복제하지 않는다. 공개 전 법률 검토 항목으로 남긴다.

## 데이터 경계

정적 정의와 회차 상태를 분리한다.

### CompanyDefinition

- `companyId`
- `countryCode`, `industryIds`
- `nameHistory[]`, `aliases[]`
- `predecessorIds[]`, `successorIds[]`
- `baselineFoundedDate`, `baselineEndDate`
- `sourceIds[]`

### CompanyState

- 현금, 부채, 주식 수, 기업가치
- 직원 수와 핵심 인재
- 기술·특허·제품 역량
- 브랜드, 평판, 시장 점유율
- 지배회사와 주주 구성
- 비상장·상장·거래정지·상장폐지 상태
- 정상·유동성 위기·지급불능·회생·청산 상태

JSON은 Unity DTO가 읽기 쉽게 객체 사전 대신 명시적인 배열을 사용하고, 날짜는 ISO `YYYY-MM-DD`, 인코딩은 UTF-8, 주석은 별도 문서에 둔다.

## 역사 사건 규칙

각 사건은 다음 정보를 가진다.

- `eventId`, `eventType`
- `baselineDate`, 필요하면 `earliestDate`와 `latestDate`
- `participantCompanyIds[]`
- 선행 회사·기술·자금·독립성·시장 조건
- 성공 시 효과
- 조건 불충족 시 정책: `cancel`, `delay`, `substitute`, `transfer`
- 기준선과 달라졌을 때 생성할 뉴스 문안 키
- `sourceIds[]`

예를 들어 원래 제품 출시 전에 플레이어가 그 회사를 인수했다면, 원래 회사가 독립적으로 같은 제품을 자동 출시하면 안 된다. 기술과 팀이 유지되면 자회사 또는 플레이어 브랜드로 이전하고, 핵심 조건이 사라졌으면 지연하거나 취소한다.

## 사건의 강도

- 거시 충격: 닷컴 붕괴, 금융 충격, 공급망 충격처럼 세계 전체에 압력을 준다. 날짜 창과 강도는 비교적 고정이지만 피해 회사는 상태에 따라 달라진다.
- 산업 전환: 광대역, 검색 광고, 모바일 인터넷, 스마트폰, 앱 생태계, 클라우드처럼 기술과 수요 조건을 바꾼다.
- 회사 사건: 제품, 상장, 인수, 분사, 이름 변경, 파산은 조건부로 해결한다.
- 플레이어·AI 행동: 계약, 연구, 채용, 가격, 소송·특허 대응, 주식 거래와 M&A로 위 사건을 바꾼다.

## 인수합병과 퇴출

회사를 단순 삭제하지 않는다. 다음 방식으로 상태를 전환한다.

- 우호적 인수와 주식 교환 합병
- 적대적 공개매수와 경영권 방어
- 자회사 편입과 독립 브랜드 유지
- 사업부·특허·인력만 사는 자산 인수
- 부실기업 인수와 채무 승계
- 회생, 청산, 상장폐지, 후속 법인

경쟁사를 망하게 하는 행위도 임의 버튼이 아니라 더 좋은 제품, 가격 경쟁, 공급망·인재·특허 선점, 부채와 현금흐름 악화, 인수 후 분할 같은 시뮬레이션 결과로 발생한다.

## 출처 정책

- 정확한 날짜와 법인명은 기업 공식 연혁·IR, 거래소 공시, 규제기관 서류 등 1차 자료를 우선한다.
- 모든 사실에는 `sourceId`를 연결하고 제목, URL, 발행 주체, 확인일을 저장한다.
- 출처가 충돌하면 확정값을 추측하지 않고 `needsReview`로 둔다.
- 주가를 역사적 숫자 그대로 복제하는 것과 역사 사건 기준선을 제공하는 것은 분리한다. 게임 주가는 회차 상태와 결정론적 시장 엔진이 계산한다.
